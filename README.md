# 寻径 · ArUco 室内语音定位原型

> 当前默认测距行为以下方“距离粗估回退与显示稳定化”为准：已增加尺度粗估回退，并将历史结果保留改为 800 ms 后标记、连续 3 秒无成功测量才清空。

## 距离粗估回退与显示稳定化（最新）

普通页、实验页默认“超宽松粗估”的像素门槛改为进入 2 px、保持 1 px，均按原视频坐标计算；原有粗略和较严格模式保持原参数。先尝试位姿解，失败后仅默认模式会尝试图像尺度距离。两种方法的结果进入同一中位数窗口，默认每 1 秒更新主距离，也可选择 2 秒或实时原始值。只要同一目标持续获得任一种有效结果，就不会因求解方法变化而清空窗口。

尺度粗估算法由 `scale-distance.js` 供两页共用。将码体边长转换为米，将四角转换到归一化相机坐标；求两组对边的平均长度 `a`、`b`，取 `l=max(a,b)`，估算 `z=s/l`，再由中心视线 `(xc,yc)` 得到斜距 `z*sqrt(1+xc²+yc²)`。使用较长的一组可以减轻单轴透视压缩影响，但倾斜、纸张变形和角点误差仍可能造成明显距离偏差，此方法只用于大概距离。

普通页沿用现有内参或视场角粗估。实验页仍需有效、同镜头同分辨率的标定 JSON；通过当前 OpenCV.js 提供的 `projectPoints` 数值反求未畸变视线，支持所接受的 4/5/8/12/14 项畸变系数。每角点最多 15 次迭代，像素残差不超过 0.1 px 才使用；无法收敛、角点退化、非有限值或距离超过 100 米时不输出新粗估。没有标定时不会在实验页启用猜测的相机参数。

显示和计时规则：

- 主区域统一显示“大概距离”和该汇总结果时间。首次成功立即显示；后台仍实时求解。
- 一帧失败立即取消本帧原始测量及记录资格，但不立刻改写主区域提示。
- 连续 800 ms 无成功测量后才标为“上次测量”；连续 3 秒无成功测量才清空数字并显示“等待测量”。失败不会刷新时间。
- 保留计时按最近一次成功测量计算，显示的结果时间仍保持真实汇总时间，不冒充刚刚测得。
- 到汇总时刻即使当前帧失败，也可使用窗口中已有的有效样本；没有样本时不虚构新结果。进入历史状态后，恢复状态随下一次汇总发布更新。
- 目标、尺寸、标定、模式、显示间隔、相机或分辨率发生切换，以及停止/隐藏页面时，立即清空窗口和旧结果。
- 失败原因放在展开详情中；主区域不会每帧交替显示“无法测量”与距离。

原始记录新增 `method: "pose" | "image-scale"`。尺度粗估的 `rvec`、`tvec`、`translation`、`tiltDeg`、`axisPlaneDeg`、`planeDistanceM`、`rmsPx` 和 `reprojectionPx` 均为 `null`（按各页原有字段使用），不借用旧角度。页面和语音明确表示“角度暂不可用”。汇总中的 `method` 仍表示 `median/raw`，新增 `methodCounts: {"pose": N, "image-scale": M}`；保留旧字段以便现有实验分析继续使用。仅有历史值时不能新增实验记录。

验证：`node --test demo/tests/*.test.cjs`，本次 52 项通过。包含尺度粗估单位、离轴斜距、图像缩放、角点次序、全部畸变系数长度的实际 OpenCV.js 反求、反求失败、默认模式回退、严格模式不回退、空角度渲染/播报/导出、交替成功失败不清空、800 ms/3 秒边界、汇总时刻失败和各种设置重置。无头 Chrome 的两页合成数据检查通过，并检查了截图、模式切换和记录；这不包含真实摄像头识别或手机精度验证。

手机验收建议：同一标记分别静止、轻晃、逐渐靠近、倾斜及短暂移出画面，确认短暂失败不会清空数字；移出超过 3 秒后应回到等待。展开详情查看位姿与尺度粗估的切换，比较卷尺斜距，单独记录倾斜场景的误差。

## 距离与标记平面角度

开始识别前，在页面填写当前打印标记的实际黑色正方形边长（不含白边和裁剪框，默认 50 mm）。同一 ID 的多种打印尺寸必须手动切换边长；部署时可在 `LOCATIONS` 的对应条目添加 `sizeMm: 80`，该配置优先于页面输入。

识别连续确认后，使用四角与已知边长进行平面单应性姿态估计，显示摄像头到标记中心的直线距离、到无限延伸标记平面的垂直距离，以及摄像头光轴相对于平面法线的倾斜角。正对时倾斜角为 0°、光轴与平面夹角为 90°。这不是人体朝向，也不是用 IMU 测出的手机外壳角度。点击“播报当前距离与角度”可听取当前测量，不会逐帧打断转向语音。

默认使用假定的 60° 水平视场角和居中的主点，**仅为未标定粗估**。可调整视场角，或在页面展开内参设置，输入实际摄像头标定结果：

```json
{"width":1280,"height":720,"fx":1100,"fy":1100,"cx":640,"cy":360}
```

以上数字仅示范格式，不能当作你的手机参数。焦距和主点单位为像素，宽高为标定图像尺寸。程序按当前检测画面缩放内参；画幅不符会拒绝测量。参数必须对应同一镜头、画幅和变焦设置。本版未做镜头畸变校正，输入内参后仍是实验估计；避免超广角及画面边缘，不能用于可靠的避障或安全距离判定。设置仅在当前页面有效。

标记太小、严重倾斜、重投影误差过大时拒绝输出；标记丢失、修改设置、停止识别时清除测量，播报也拒绝使用超过 1 秒的旧测量。无论测量是否成功，位置识别和转向提示继续工作。

验证：运行 `node --test demo/tests/*.test.cjs`。实机用直尺分别核对 0.3、0.5、1 米的中心距离，再测试正对、约 30°、约 60° 倾斜；使用 30 mm 与 80 mm 打印标记并同步更改设置，检查不同尺寸的一致性。没有真实摄像头标定和实测数据时，不承诺具体精度。

## 打印不同尺寸的标记

在项目根目录运行：

```bash

```

输出到 `demo/print_sheets/`：每个标记 ID 单独一张 A4 PNG（300 DPI），同一张图片包含 30、40、50、60、80 mm 五种尺寸。尺寸是 **ArUco 黑色标记本体的边长**，不包含外围白边和裁剪框。每个标记与正方形黑色裁剪框之间留有 5 mm 白边，沿框裁剪时请保留这些白边。

打印时选择 A4、**实际大小 / 100%**，关闭“适合页面”“填满页面”等缩放选项；用直尺检查底部的 50 mm 校验线。图片内使用英文尺寸标签，避免依赖系统中文字体。

自定义尺寸及分辨率（单位 mm）：

```bash

```

也支持 `--input-dir`、`--output-dir` 和 `--quiet-mm`；默认路径相对于脚本目录，与运行时所在目录无关。若自定义尺寸无法排入一张 A4，脚本会报错，不会自动缩小标记。原始 `markers/` 图片保持不变。

## 空间音频
- 请使用双声道耳机，先点击“试听左侧”“试听右侧”确认方向；无需打开摄像头。手机扬声器、单声道输出或系统的单声道辅助设置会影响方向效果。
- 扫描到有转向配置的标记时，先播放约 0.6 秒的双脉冲方向提示音，然后播报位置和“请左转”或“请右转”。方向音采用 Web Audio `PannerNode` 的 HRTF 空间化；中文语音沿用浏览器语音合成，本身不做空间化。
- ID 1（一楼电梯）演示右转；ID 3（二楼主走廊）演示左转；ID 0、2、4 只播报位置。这是演示数据，实际使用前须按现场路线调整。
- “重播提示”完整重播最近识别位置的方向音和语音；“停止提示”取消当前播放，但不停止摄像头或之后的识别提示。“停止”同时停止识别和播放。
- 方向相对于听者，假设用户沿预设路线接近标记；不使用标记在画面中的左右位置推断方向，也不追踪手机或头部朝向。未来可由 IMU 和路线判断层输出方向，再调用独立的 `playDirection(direction, token)` 播放接口；`token` 是当前播放批次，用于取消旧提示。
- 音频在点击开始、试听或重播时初始化或恢复。空间音频失败会保留语音和文字，语音合成失败会保留方向音和文字；音频状态区域显示降级信息。若手机切后台后无声，请回到页面点击试听或重播恢复。

在 `LOCATIONS` 中配置可选的 `direction`：

```javascript
1: {name: '一楼电梯', message: '您目前位于一楼电梯附近。', direction: 'right'},
3: {name: '二楼主走廊', message: '您目前位于二楼主走廊。', direction: 'left'}
```

只有 `left`、`right` 会触发方向提示；省略该字段则只播报 `message`。请勿在 `message` 中重复添加同一转向，页面会自动追加中文转向指令。

### 验收方法
- HTTPS 页面连接耳机，在 Android Chrome 和 iOS Safari 上分别检查首次点击试听、开始识别、切后台后重播的播放表现。

- 拒绝摄像头权限时应显示启动失败，仍可试听；不支持 Web Audio 或语音合成时应显示对应状态，并保留可用的提示方式。
- 自动化测试使用模拟浏览器和音频节点验证流程；实际声像、耳机声道、手机播放权限与真实摄像头识别需要上述实机验收。

## 字典一致性
- Python：`cv2.aruco.DICT_ARUCO_ORIGINAL`
- 浏览器：`new AR.Detector({dictionaryName:'ARUCO'})`
- **不要使用上一示例的 DICT_6X6_250 标记来测试此网页**；字典不同。

## 原型局限
- 识别成功只证明看到某个被登记的标记，不能自动提供连续位置/绝对朝向/距离/避障能力。
- 消息中的方位或危险提醒必须基于现场验证，不应随意使用“左转”“前方安全”等词语。
- 测试时应有陪同人员并保留盲杖等常规辅助方式。

### 棋盘与本地标定

安装工具依赖（USTC 镜像若无匹配包，可改用 `https://pypi.org/simple`）：

```bash
python -m pip install -i https://mirrors.ustc.edu.cn/pypi/simple opencv-contrib-python Pillow
python demo/generate_calibration_board.py
```

`calibration_board.png` 是 300 DPI A4 横向：**10×7 方格、9×6 内角点、20 mm 方格边长**。按实际大小 100% 打印，关闭适应纸张，并实量多个方格总长确认比例。平贴硬板。采集 15–25 张不模糊的完整棋盘，覆盖画面中心、边缘与四角，以及近远和不同倾角；重复姿态不算有效覆盖。本工具只要求至少 10 张可检测图，不会自动证明覆盖充分。镜头、对焦/变焦、分辨率和裁剪模式应保持一致；换相机模式重新采集标定。

把下载的 PNG 放入一个目录（不要放打印板原图），执行：

```bash
python demo/calibrate_camera.py captures --cols 9 --rows 6 --square-mm 20 --output calibration.json
```

输出 schemaVersion=1，含唯一 `id`、`createdAt`、`width/height`、3×3 `cameraMatrix`（像素）、`distCoeffs`（OpenCV 顺序 k1,k2,p1,p2,k3…）、`board`（innerCols/innerRows/squareMm）、总体 `rmsPx`、每张误差 `images` 及检测失败 `rejected`。不同有效图片分辨率混合会报错。高误差照片需检查并剔除后重新标定；低误差也不保证良好覆盖。

在实验页导入 JSON。实验页要求实际视频尺寸与标定尺寸完全一致，不假定不同视频模式只是等比缩放。检测角点按实际缩放比例还原到视频坐标，内参与畸变参数保持原标定单位。标定必须对应相同镜头、画幅、变焦；浏览器无法仅凭 JSON 验证物理镜头一致。

### 位姿与记录

填写实际黑色码体边长 mm（不含白边/裁剪线/纸张）。使用既有 `ARUCO` / OpenCV `DICT_ARUCO_ORIGINAL`，没有更换字典。对象坐标原点在码中心，IPPE_SQUARE 物理角点依次为 (-s/2,+s/2,0)、(+s/2,+s/2,0)、(+s/2,-s/2,0)、(-s/2,-s/2,0)，一一对应检测器顺序；循环旋转起点只改变平面坐标轴，不改变距离。相机坐标 x 向右、y 向下、z 向前；s 使用米。OpenCV.js 4.10.0-release.1 `solvePnP(IPPE_SQUARE)` 使用内参与畸变，输出旋转向量与平移，距离是 `hypot(tx,ty,tz)`。

页面拒绝过小标记、非凸或乱序角点、相机后方点、无解、非有限值、超过 100 m 或重投影 RMS 超过 3 px 的结果。单平面存在近似双解，当前 JS 绑定只返回首选解，**未枚举/消除双解**，屏幕和记录始终保留这个质量提示；不可据此宣称可靠朝向。无平滑，显示原始测量。丢码立即清空当前值，暂停帧超过约 0.6 秒也失效；页面隐藏释放摄像头。输出不是人脚下到码的地面距离，更不是全局定位。

填卷尺参考斜距（相机镜头位置到码中心，单位米），每次重新摆放手机、等待清晰识别、点击一次记录；按钮有 2 秒最短间隔，不能证明每次独立，操作者须确保重新布置。JSON 导出包含标记 ID、码体尺寸、标定 ID、视频/检测尺寸、时间、参考斜距、原始估计、tvec/rvec、误差、歧义说明和角点。

### 测距状态机与像素阈值

实验页现使用 `idle → acquiring → tracking` 状态，短暂质量失败进入 `recovering`，连续失败后进入 `tooSmall` 或 `unstable`。进入/重新进入 tracking 需最短边 ≥16 原视频像素且连续 3 次求解合格；已在 tracking 时允许最短边 ≥12 px，以滞回避免边界抖动。每个不合格观测立即取消当前可记录测距，主提示延迟确认状态类别，不保留伪实时距离。丢码、停机、换目标、改尺寸/标定/检测分辨率会重置状态。没有对距离做数值平滑。

绿色框只代表检测器成功解码，不代表姿态精度合格。“标记过小”检查的是图像中最短边，不是你输入的毫米边长；远距离、小码体或大倾角都会减小最短边。页面同时显示原视频/检测图像中的最短边。不要通过填写更大的毫米边长绕过此检查，那只会放大错误的距离结果。

检测默认最大宽度改为 960 px，可选 640/960/1280，始终不超过原视频宽度。提高检测分辨率可以保留角点细节，但不能增加真实光学信息；阈值仍以原视频坐标计算，不随检测缩放随意改变。性能较弱的手机可退回 640，实际更新率在画面下方显示。12/16 px 为实验启发式门槛，不构成测距精度保证；优先靠近、减少倾斜、使用更大打印码体并实测。

### 粗略测距模式（默认）

实验页新增模式选择，以下设置取代前文单一的 12/16 px 门槛描述：

| 模式 | 进入最短边（原视频 px） | 保持最短边（原视频 px） | 重投影 RMS 上限 |
| --- | --- | --- | --- |
| 粗略测距（默认） | 8 | 6 | 6 px |
| 较严格测距 | 16 | 12 | 3 px |

两者均需连续 3 次合格检测才进入/恢复测距，均不使用旧距离冒充当前结果。切换模式清除当前值并重新确认。粗略显示保留两位小数，但实验记录仍保留完整原始距离，同时保存 `qualityMode` 与 `qualityThresholds`，便于对比两种模式。相机标定及物理码体尺寸要求不变，姿态无解、非有限结果、相机后方点等检查仍保留。

降低阈值能让较小的已识别标记进入求解，但不提升实际图像细节，也不能恢复检测器未解出的 ID。尤其只有 6–8 个原视频像素的短边时，1 px 的角点误差影响可能很大；粗略模式是可用性取舍，不是精度承诺。建议按实际需要选择模式并用卷尺对比。

## 实时测量与低频稳定显示（当前行为）

普通页和实验页新增“数值更新”选择，以下说明替代此前“逐帧显示/丢码立即清空主距离”的描述：

- 默认“每 1 秒汇总”：后台继续原有约 150/180 ms 的检测和求解节奏，首次成功立即显示；之后每秒计算最近 1 秒有效距离的中位数。
- “每 2 秒汇总”：按相同方式使用最近 2 秒样本。它会延后反映真实移动，适合观察较稳的读数。
- “实时原始值”：每次有效求解直接显示最新距离，不汇总。单样本窗口也允许输出，不增加手机静止或连续样本要求。
- 展开“实时原始测量详情”可查看最新原始距离、时间与重投影误差；实验页还保留平移向量等。主距离汇总不改动这些原始值。
- 普通页的角度和平面距离来自窗口中距离最接近中位数的真实样本（同差值时取较新样本），主区域标明“对应样本”。旋转向量不求平均。
- 失败或丢码时，原始值立即失效；主区域保留已显示的结果并明确标注“上次测量”和时间。最多保留至该显示结果最后一个样本之后 2 秒，失败不刷新计时；到期显示“等待测量”。无新帧时也自动过期。
- 修改 ID、码体尺寸、相机参数、测距模式、分辨率或显示间隔，以及停止/隐藏页面，会清空窗口和旧显示，避免不同设置混合。可取得的镜头 ID/zoom 变化也会分开窗口。
- 普通页手动播报读取汇总结果；若是历史值，会先说明“上次测量”和时间。导览位置播报和空间音频逻辑保持原样。
- 实验记录仍要求原始结果有效。导出中的顶层 `distanceM`、`tvec`、`rvec` 继续是原始结果；新增 `displaySummary`，包含 `intervalMs`、`distanceM`（汇总距离）、`method`（median/raw）、`sampleCount`、`windowStartTime`、`windowEndTime` 和 `representativeTime`。仅有历史显示时不能新增实验记录。

共享模块为 `measurement-display.js`。发布时将它与 `index.html`、`lab.html`、`lab.js` 同步上传，已有 `pose.js`、`lab-pose.js` 仍需保留。
