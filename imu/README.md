# 阶段 2：手机 Web Bluetooth 姿态接收

## 阶段 3：相对朝向测试（当前等待实机验收）

工具与设置 → IMU 面板底部新增“相对朝向 · 阶段 3 测试”，仅显示结果，尚未接入声音或扫码路线。

1. 连接真实 IMU，按最终使用方式固定在胸前，身体直立并保持手机可操作。点击“记录起始朝向”。
2. 身体缓慢向右转约 90°，保持直立，点击“已向右转约 90°”。允许实测角度 45°–135°；转动太小会拒绝。向右的动作必须由测试者正确执行，算法不能独立判断用户实际向左还是向右转。
3. 当前相对转角应接近 +90°。转回起始朝向，选“右转 90°”：身体向右转到约 0°、45°、90° 时，目标应依次在右侧、右前方、正前方；左转目标对称。显示经过约 120 ms 时间常数的平滑。
4. 可以“以当前方向归零”，保留已学到的安装转动方向，清除旧目标。手动目标范围 -180°–180°，右正左负，均相对于最近起始/归零朝向。
5. 缓慢跨越 ±180° 并转满一圈，数值可在边界换号，目标方向不应绕远路跳变。轻微前倾应可继续，大幅偏离校准平面时显示无效并停止输出声源方向。恢复直立后可恢复；若期间发生超时则需重新校准。
6. 断线或最后姿态超过 500 ms 后，校准和目标失效；重连仅收数据，需重新做上述两点校准。解码器报告坏包时也清除校准，避免继续使用不可信参考。

模块 `orientation.js` 独立于 DOM、BLE 和音频。`OrientationTracker` 提供 `update(packet,time)`、`beginCalibration()`、`finishRightTurn()`、`zero()`、`setTarget(degrees)`、`reset(reason)`、`snapshot()`。`snapshot()` 返回 `state,calibrated,usable,headingDeg,targetDeg,relativeTargetDeg,source,receivedAt`；不可用时角度与 source 不输出。`source` 使用 Web Audio 坐标（右 +X、前 -Z），本阶段不创建音频节点。面板导出共享的 `orientationTracker` 供后续整合复用。

安装方向校准通过两个实际四元数学习水平转动所在的四元数平面，不假设传感器 Z 轴或厂家主动/被动旋转约定；原始包保持不变，仅计算副本归一化。模长偏离 1 超过 0.1 或相对校准平面偏离超过 20° 判为无效。固定安装、直立的单轴转身是该模型的前提；两点校准无法检测校准过程中混入的身体倾斜，也无法识别沿同一转动平面的 AHRS 漂移。改变佩戴方式或怀疑方向不准时重新校准，不将此结果解释为绝对磁北或连续位置。

请反馈左右 90°、回正、跨界、轻微倾斜、断线重连的实测结果；阶段 3 验收后再进入独立空间音频测试页。

现有入口为主页面 → 工具与设置 → IMU 蓝牙与实时姿态。固件继续使用当前版本，无需重新烧录；手机通过受信任的 HTTPS 地址直接在 Android Chrome 打开页面。

## 手机验收

1. ESP32 与 IMU 上电，断开 nRF Connect 等其他客户端；点击“连接设备”，选择 ArUco-IMU-C3。
2. 状态应为“已连接 · 已订阅”，收到真实包后显示四元数与有效频率。稳定运行两秒后，正常目标约 20 Hz，以实际硬件接收情况为准。
3. 56 字节完整包显示 Roll/Pitch/Yaw、加速度和角速度；切换角度单位应满足 rad × 180/π = 度。20 字节包只显示四元数，其他字段显示“未提供”。MTU 由手机系统协商，网页没有手动设置 MTU 的接口。
4. 返回扫码页识别已登记的 ArUco，再返回工具页，确认 BLE 仍连接、数据继续变化，原有路线和中文播报正常。
5. 关闭 ESP32 电源，确认断线提示、读数清除。重新上电后点击“重新连接”，确认恢复通知且每包只计数一次。取消设备选择也应允许再次连接。
6. 若连接但没有首包，三秒后应提示未收到有效数据；已有有效数据后超过 500 ms 未更新，应显示超时及历史读数。坏包应计入无效计数，不能刷新有效数据时间。
7. 按实际胸前佩戴方式记录：静置、向右转约 90°、回正、向左转约 90°、轻微前倾时的四元数和完整包欧拉角。记录模块轴标识、安装方向及每个动作前后的 HEX，可使用“复制 HEX”。这些数据用于下一阶段确定身体轴映射，当前不推断身体 Yaw。

请反馈手机型号/系统、Chrome 版本、20/56 字节包型、稳定接收频率、上述动作的数据，以及扫码/断线重连结果。阶段 2 完成后暂停，验收后再进入相对朝向追踪。

## 共享接收接口

面板与后续导航模块通过 `import {imuReceiver} from './imu/receiver.js'` 使用同一个实例（导入路径相对于主目录的模块）。不要在业务模块中再次构造 `ImuBluetoothClient`。

- `connect(true)`：在用户点击回调中直接调用，选择设备并订阅通知；`connect(false)` 重连已选设备；`disconnect()` 主动断开。
- `packet` 事件：`{packet, hex, time}`，`time` 为页面 `performance.now()` 毫秒时间；packet 字段沿用 `decodePacket()`，所有测量数组只读。欧拉角原始单位始终是 rad。
- `state`、`invalid`、`error`、`message` 事件：沿用现有客户端事件。
- `snapshot()`：读取 `{state, freshness, usable, ageMs, packet, receivedAt, rateHz, valid, invalid, duplicates}`。只有 `usable === true` 才可将数据用于导航；超时保留的 packet 仅用于诊断。
- `freshness` 事件：状态变化时提供同样的快照；状态为 `disconnected`、`waiting`、`fresh`、`stale`。现有面板每 250 ms 调用 `checkFreshness()`，即使没有通知也会检测超时。业务模块可随时读取 `snapshot()` 获取即时结果。

页面隐藏工具面板不释放连接；`pagehide` 时释放连接。重新连接必须等待新包，历史数据不会作为新会话姿态使用。当前阶段未新增姿态校准或空间音频控制。

## 离线测试

在 `indoor-guide/imu` 目录运行 `npm test`。测试仅使用 Node 内置测试工具，无需安装依赖；合成二进制包只出现在测试中。协议完整包 fixture 来自现有固件 C++ 编码测试。离线通过不代表真实蓝牙或手机音频已经验收。
